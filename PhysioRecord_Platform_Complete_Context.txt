1. IDENTITY, MISSION & CORE PHILOSOPHY
--------------------------------------------------------------------------------
- Application Name: PhysioRecord (فيزيو ريكورد) — Clinical Physical Therapy EHR
- Target Users: Physical therapy & rehabilitation outpatient clinics in Iraq
  (built for desktops, laptops, tablets, and mobile browsers).
- Primary Language & Locale:
  - Arabic (default, full RTL `dir="rtl"`), using Gregorian calendar with Latin
    digits (`ar-IQ-u-ca-gregory-nu-latn`), Iraqi Arabic month names
    (كانون الثاني، شباط، آذار، ... تشرين الثاني، كانون الأول), and dd/mm/yyyy
    display dates everywhere.
  - Full bilingual English toggle (`en-GB` / `en-US`, LTR `dir="ltr"`).
- Architecture: 100% Local-First, Zero-Cloud, Encrypted Client-Side EHR.
  - All patient PHI and clinical documentation stays strictly inside the clinic's
    local browser storage (IndexedDB via Dexie.js, envelope-encrypted via Web
    Crypto API AES-256-GCM).
  - No remote backend, no telemetry, no cloud sync. Data portability relies on
    encrypted `.ptbackup` (v1.1) files exported/restored by clinic staff.
- Clinical Domain Hierarchy:
  Patient -> Episode of Care -> Clinical Session -> 1:1 SOAP Note (+ Append-Only Clinical Addenda)

4. CRYPTOGRAPHY, VAULT LIFECYCLE, INDEXEDDB & BACKUP ENGINE
--------------------------------------------------------------------------------
A. Provider Mount Order (`src/App.tsx`):
   ThemeProvider -> LanguageProvider -> CurrencyProvider -> VaultProvider ->
   PatientProvider -> EpisodeProvider -> SessionProvider -> AppContent

B. Envelope Encryption Specification (`src/crypto/vault.ts`):
   1. Key Derivation Function (KDF):
      - Algorithm: PBKDF2-HMAC-SHA256
      - Iterations: 600,000 (`DEFAULT_PBKDF2_ITERATIONS = 600_000`)
      - Salt: 16 bytes CSPRNG (`SALT_BYTES = 16`)
      - Output: 256-bit AES-GCM Key Encryption Key (`vaultKek`)
   2. Master Data Encryption Key (DEK):
      - Random 256-bit AES-GCM key (`extractable: false` CryptoKey in WebCrypto memory).
      - Wrapped by `vaultKek` inside `db.vaultMeta`.
      - Bound to `vaultGeneration` via `bindDekToGeneration()` to prevent cross-lock/generation leakage.
      - Plaintext password is NEVER stored in IndexedDB, localStorage, or sessionStorage.
      - Verifier token plaintext `'PHYSIORECORD_VAULT_OK'` validates password on unlock.
   3. Record-Level Encryption:
      - Cipher: AES-256-GCM with fresh random 96-bit (12-byte) CSPRNG IV per write.
      - Additional Authenticated Data (AAD): cryptographically binds ciphertext to
        table/store name, record `id`, parent foreign keys (`patientId`, `episodeId`, `sessionId`),
        `recordCryptoVersion` (1), and `dekVersion` (1). Any tampering throws `DecryptionAuthError`.
      - Atomic GCM Nonce/Usage Counter: Every encryption reserves from `encryptionInvocationCount`
        in `db.vaultMeta` transactionally BEFORE encryption (`MAX_GCM_INVOCATIONS_PER_DEK = 1,000,000`;
        exceeding throws `DekExhaustedError`, requiring DEK rotation / restore).
   4. Memory Scrubbing & Auto-Lock (`src/context/VaultContext.tsx`):
      - On `lock()`, `dek` is dropped and PatientContext / EpisodeContext / SessionContext immediately
        scrub all decrypted React state arrays (`patients = []`, `episodes = []`, `sessions = []`).
      - Inactivity Auto-Lock checks activity + visibilitychange hidden-tab timestamps.
      - Configurable in Settings -> Security:
        - Presets: 1 min, 5 min, 10 min (default), 15 min, 30 min
        - Custom manual duration: 1 to 1440 minutes
        - Disable option: `0` ms ("Never / أبداً") skips inactivity auto-locking cleanly.

C. IndexedDB Schema (`src/db/db.ts`, `PhysioRecordDB` — current version 6):
   18 total tables. Plaintext clinical fields are NEVER left unencrypted on entity wrappers (legacy v1
   plaintext metadata stripped in v2/v3 `.upgrade()`).
   - 15 Portable Clinical Stores (registered in `CLINICAL_STORES_REGISTRY` in `src/db/registry.ts`):
     1. `patients`           (&id, createdAt, updatedAt, isArchived)
     2. `episodes`           (&id, patientId, createdAt, updatedAt)
     3. `sessions`           (&id, episodeId, patientId, createdAt, updatedAt)
     4. `soapNotes`          (&id, &sessionId [unique 1:1], episodeId, patientId, createdAt, updatedAt)
     5. `clinicalAddenda`    (&id, sessionId, patientId, targetId, createdAt)
     6. `appointments`       (&id, patientId, createdAt, updatedAt)
     7. `waitingList`        (&id, patientId, createdAt, updatedAt)
     8. `invoices`           (&id, patientId, episodeId, createdAt, updatedAt)
     9. `payments`           (&id, invoiceId, patientId, createdAt, updatedAt)
    10. `expenses`           (&id, createdAt, updatedAt)
    11. `auditLogs`          (&id, patientId, episodeId, createdAt)
    12. `staffState`         (&id, updatedAt)
    13. `episodeClinical`    (&id, &episodeId, patientId, createdAt, updatedAt)
    14. `customWidgets`      (&id, createdAt, updatedAt)
    15. `migrationReports`   (&id, createdAt)
   - 3 Excluded Device/Technical Stores (`EXCLUDED_DEVICE_STORES`):
    16. `vaultMeta`          (&id)
    17. `episodeSequences`   (&episodeId) -> holds keyed HKDF-SHA256 HMAC tokens (`allocatedTokens`) +
                             monotonic `lastSequenceNumber` for atomic cross-tab session numbering
    18. `migrationState`     (&id) -> resumable state for localStorage -> Dexie migration

D. Encrypted Backup & Restore (`.ptbackup` v1.1 in `src/crypto/backup.ts` & `src/crypto/recovery.ts`):
   - Format: `'1.1'`, Magic: `'PHYSIORECORD_BACKUP_V1.1'`
   - Key Hierarchy:
     - Separate backup password -> PBKDF2-HMAC-SHA256 (600,000 iter, 16-byte `backupSalt`)
     - HKDF-SHA256 with 32-byte `hkdfSalt` + strict domain separation info strings:
       * `'physiorecord-backup-dek-wrap-v1.1'` (wraps source DEK)
       * `'physiorecord-backup-payload-enc-v1.1'` (AES-256-GCM encrypts payload)
   - Canonical Header AAD: 20 header metadata fields serialized strictly to prevent downgrade/tampering.
   - Mobile Memory Protection: `MAX_BACKUP_SIZE_BYTES = 25 MB` (warning banner above `20 MB`).
   - Restore Workflow:
     1. Preview inspection (`inspectBackupPreview`) verifies password + referential integrity (`patients -> episodes -> sessions -> ...`).
     2. Mandatory pre-restore safety snapshot saved into logically isolated `PhysioRecordEmergencyRecoveryDB` (`recoverySnapshots` table) and downloadable/saveable externally to OS disk (`saveExternalRecoveryBackupFile`) before overwriting `PhysioRecordDB`.
     3. Generates a brand-new random DEK on restore, resets `encryptionInvocationCount` to 0, re-encrypts all records atomically.

5. CRITICAL INVARIANTS & CLINICAL SAFETY RULES (DO NOT VIOLATE)
--------------------------------------------------------------------------------
1. NEVER hardcode real or fake patient/appointment/invoice rows in default runtime views:
   - Empty databases start completely empty (`[]`).
   - `ClinicOperationsService.ensureHardcodedMocksPurgedOnce()` actively strips legacy mock IDs (`appt_default_*`, `wait_1/2`, `inv_iqd_1001/1002`, `exp_1/2`).
   - Synthetic demo records (`SYNTHETIC_PATIENTS`, `syn-patient-*`, `isDemo: true`) are strictly opt-in via `SyntheticDataModal` or `SettingsModal -> Developer` and visibly badged `<DemoBadge />`.
2. Finalized Records Are Immutable:
   - Once a session (`status === 'finalized'`) or SOAP note is finalized, updates/deletes are strictly blocked (`CannotDeleteFinalizedRecordError`).
   - Canonical SHA-256 integrity seals (`CURRENT_SEAL_VERSION = 1`, `canonicalizeForSeal`) verify finalized session/SOAP integrity.
   - Any post-finalization amendment MUST be written as an append-only record in `db.clinicalAddenda` with a required `AddendumReason`.
3. Single Writer Rule (`Amendment D`):
   - `ENABLE_LEGACY_SOAP_MODAL_ROM_MMT_BODYCHART_WRITES = false`.
   - Active ROM/MMT/BodyChart/Neuro/SpecialTests/Gait/Scales data is edited via `MasterPatientChart -> ActiveExamCanvas -> episodeClinical`, NOT via legacy `SoapModal`.
4. Patient Hard Deletion Safeguard:
   - Archiving (`archivePatient`) is the default safe operation. Hard deletion checks all dependent records (`auditPatientDependentRecords`) and throws `PatientHardDeletionBlockedError` unless requirements/verified backup proof are satisfied.
5. Schema & Migration Discipline:
   - NEVER mutate existing historical Dexie `.version(N)` blocks (keep v1..v6 intact). Always add a new `.version(N+1)` migration when changing IndexedDB stores/indexes.
6. LocalStorageKeys Reference:
   - Vault/App Config & Operations keys (`ClinicOperationsService`, Contexts, MRN):
     * `physiorecord_theme_mode`               ('light' | 'dark')
     * `physiorecord_preline_theme`            ('theme-clinical-teal' | ...)
     * `physiorecord_language`                 ('ar' | 'en')
     * `physiorecord_primary_currency_code`    (ISO 4217 code, default 'IQD')
     * `physiorecord_active_staff_v2`
     * `physiorecord_staff_roster_v2`
     * `physiorecord_admin_pin_v1`             (default '1234')

     * `physiorecord_show_exercise_library_v1` ('true' | 'false', default hidden `false`)

7. UI/UX DESIGN SYSTEM & CODING CONVENTIONS FOR CLAUDE
--------------------------------------------------------------------------------
When modifying or extending PhysioRecord UI or code, ALWAYS adhere to these rules:
1. Typography & Fonts (`src/index.css`):
   - Sans stack: `Inter`, `IBM Plex Sans Arabic`, `Noto Sans Arabic`, system-ui.
   - `PhysioMono` is strictly Unicode-range restricted to ASCII/Latin/digits so Arabic text NEVER falls back to monospace; `:lang(ar)` enforces `letter-spacing: 0 !important`, `text-transform: none !important`, `line-height: 1.6`.
   - Minimum font size floor: 12px (`0.75rem`) everywhere (`.text-[8px]..[11px]` clamped to 12px).
2. Themes & Modes:
   - Support BOTH Light and Dark mode (`dark:` classes paired with Preline CSS variables like `bg-layer`, `bg-card`, `text-foreground`, `text-muted-foreground-1`, `border-layer-line`, `bg-primary`, etc.).
   - Support all 4 Preline themes (`theme-clinical-teal`, `theme-ocean-blue`, `theme-royal-indigo`, `theme-emerald-care`).
3. RTL / Bidirectional Numeric Safety:
   - NEVER render raw numbers, fractions (`3/10`), dates (`12/11/2026`), phone numbers, times (`10:00 ص`), or currencies directly inside RTL Arabic flow without isolation.
   - Always use UI Primitives from `src/components/ui/Primitives.tsx`:
     `<Num />`, `<Fraction />`, `<Money />`, `<MoneyInput />`, `<PhoneInput />`, `<DatePickerInput />`, `<TimePickerInput />`.
   - Do NOT use native `<input type="date">` or `<input type="time">` (use `<DatePickerInput />` and `<TimePickerInput />`).
4. Control Contrast & Touch Targets:
   - Inputs/selects/textareas keep visible borders (`var(--control-border)` >= 3:1 contrast) and clear focus rings.
   - Interactive controls have min-height 32px desktop, 40px mobile (`button:not(.compact-btn)`). Use `.compact-btn` only for intentionally small chip/badge controls like segment buttons or close pills.
5. Bilingual Consistency:
   - Check `language === 'ar'` / `isRtl` everywhere. Never hardcode English-only errors or untranslated UI labels, and avoid cramming two languages onto every single button unless clarification is clinically necessary.
